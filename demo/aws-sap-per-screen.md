# The AWS and SAP parts, per screen

Generated by `tools/aws_sap_card.py` from `tools/aws_sap_map.py`. The same file puts
the one-line strip at the foot of every console page, so what a judge reads here is
what the screen in front of them says. `tools/ui_component_gate.py` fails if the two
ever disagree.

Rubric line this answers: **technical execution on AWS/SAP, 25 percent**. The answer
is components, screen by screen, and an honest list of what the account gate blocks.

## `/` — Console

**What the screen claims.** A buyer asks in plain words and reads an answer whose numbers are checked against the records before it is shown.

**AWS.** AWS Lambda `pasok_agent` (us-west-2, public Function URL) answers the same question class through `{"action":"ask"}`

**SAP.** SAP AI Core orchestration `d8c092efb8980093`, model `gpt-5.4-2026-03-05` writes the sentence; the trace under each answer names it and its milliseconds

**Honest limit.** native Bedrock `Converse` and AgentCore Runtime are account-gated; the Lambda lane is the substitute, with Bedrock reached through Mantle

## `/orders` — Order history

**What the screen claims.** Every purchase order the loop placed, with its status and the reason it holds that status.

**AWS.** Lambda `{"action":"network"}` returns the same order summary the page shows

**SAP.** SAP AI Core wrote the plain-language rationale on every escalated order (`data/sap/rationales.csv`, 40 of 40, no template fallback)

**Honest limit.** the SAP business system itself is reached through a pluggable intake, proven against a stand-in ERP, not a live SAP write

## `/receiving` — Receiving

**What the screen claims.** What actually arrived against what was ordered, and what that says about each supplier.

**AWS.** Lambda `{"action":"sku"}` returns the same delivery and fill figures from the bundled artefacts

**SAP.** the order intake seam (file-backed default, HTTP adapter by `PASOK_ORDER_ENDPOINT`) is where a distributor's own system plugs in

**Honest limit.** no SAP business-system write path is built; the seam is the honest substitute and it is demonstrable

## `/health` — Stock health

**What the screen claims.** Days of cover per SKU, the coverage floor, and which stock is at risk of expiring.

**AWS.** Lambda `{"action":"exceptions"}` returns the same flags, sorted by the same urgency rule

**SAP.** SAP AI Core RPT-1.6 (`sap-rpt-1.6`) scored all 600 SKUs on three targets in one call: 293 stockout-Yes, 52 expiry-Yes (`data/sap/rpt_scores.csv`)

**Honest limit.** the Bedrock Knowledge Base that the proposal names for the registry does not exist; the registry is a file the Decision Agent reads

## `/transfers` — Depot transfers

**What the screen claims.** Stock that would expire where it sits is moved to a depot where it will sell.

**AWS.** Lambda lane answers from the same redirect artefact

**SAP.** the redirect decision carries its `gpt-5.4-2026-03-05` rationale like every other high-stakes action

**Honest limit.** nothing here is blocked; the transfer is planned and recorded, not executed against a warehouse system

## `/suppliers` — Suppliers

**What the screen claims.** Each principal's real lead time (p50 and p90), its fill rate, and whether either has drifted.

**AWS.** Lambda `{"action":"sku"}` carries the same supplier reliability figures

**SAP.** no SAP dependency on this screen: the numbers come from the receiving records, and it is worth saying so out loud

**Honest limit.** lead-time drift detection reports over a one-day window on this snapshot; the year of history is on `/loop`

## `/geography` — Cities

**What the screen claims.** Where the demand and the orders are, city by city.

**AWS.** Lambda lane answers from the same order and stock artefacts

**SAP.** no SAP dependency; this is a reading of the same records

**Honest limit.** city granularity is the outlet file's own field, not a geocoded feed

## `/loop` — Loop map

**What the screen claims.** The nine stages the loop runs, in order, with what each one read and wrote.

**AWS.** the four-agent reasoning layer is the same code the Lambda lane runs; the runtime is the host, the artefacts are the evidence

**SAP.** SAP AI Core `gpt-5.4-2026-03-05` writes the run report at the end of a loop (`/api/chat` streams the stages, then the model's summary)

**Honest limit.** multi-agent coordination is in-process on the Lambda; AgentCore Memory and Gateway return empty lists on this account

## `/panel` — Agent panel

**What the screen claims.** Agent state, the exception queue, one SKU traced end to end, and the approvals waiting for a person.

**AWS.** Lambda `{"action":"exceptions"}` and `{"action":"sku"}` mirror the queue and the single-SKU trace

**Honest limit.** AgentCore Memory and Gateway are empty on this account; the decision history is a durable file instead

## `/demo` — Demo page
